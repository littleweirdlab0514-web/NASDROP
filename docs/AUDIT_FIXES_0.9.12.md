# NASDrop 0.9.12 감사 수정 결과

기준: 2026-09-05, 기존 저장소 커밋 `98aa1ad`, Synology NASDrop 0.9.11.

## 수정

1. `.more` 조각은 HTTP 범위를 확인해 원래 오프셋에 반영한다. 중간 커밋이 끊겨도 중복 append 없이 재시도하며 I/O 실패 때 검증된 조각을 보존한다. 전송 모드는 작업별 저장하고 작은 파일의 빈 구간을 제거했다.
2. `stopping` 상태로 워커 종료를 기다린다. 이때 재개·삭제를 차단하고 같은 작업 ID의 중복 실행을 막는다. 결합·해시 계산은 취소를 확인하고 게시 전에 중지 상태를 다시 검사한다.
3. 서비스 종료 신호를 처리해 스케줄링을 중단하고 전송 프로세스 그룹을 종료한다. 디스크 복사·7-Zip 실행도 중단을 확인하며 상태를 저장한다.
4. 실제 GoFile 전송의 HTTP 429와 Retry-After를 공급자 공통 대기에 연결했다. 준비된 URL이 있어도 쿨다운 동안 새 작업을 시작하지 않는다. 8회의 curl 즉시 재시도는 제거했다.
5. 목록 갱신에서 압축 암호 폼 노드·포커스·선택 범위와 열린 검증 정보를 보존한다. 암호를 localStorage에 저장하지 않는다. 세션 만료 시 로그인으로 돌아간다.
6. 내부 주소의 HTTPS DSM 런처는 HTTP NASDrop 리스너에 연결한다. 공개 도메인의 HTTP/HTTPS 유지 정책은 그대로다.
7. 요청 JSON은 객체만 허용한다. 배열·null·문자열·숫자는 입력 오류로 거부한다.
8. 모든 분할 자식 종료 코드를 수집하고 실제 GET 응답에서 파일명 헤더를 수집한다. 후처리에 필요한 헤더만 남기고 쿠키 등 응답 비밀은 제거한다.

## 검증

- Python 전체 회귀 테스트 **121개 통과**.
- Node 전체 회귀 테스트 **13개 통과**.
- 로컬 HTTP 서버가 첫 구간을 2바이트 뒤 끊도록 한 실제 생성 셸 테스트: 첫 실행 실패 전파, 2바이트 체크포인트 유지, 두 번째 실행의 최종 바이트가 원본과 완전히 동일함을 확인했다.
- 부정확한 Content-Range, 로컬 I/O 실패, 본문 없는 429, 작업 취소, 쿨다운과 후처리 경합에 대한 테스트를 추가했다.
- SPK를 빌드하며 내부 package.tgz의 필수 파일·실행 권한·NASDrop 런처 제목을 검증했다. 새 transfer_parts.py도 필수 파일이다.
- 실제 공급자에 다운로드/429 시험 요청을 보내지 않았으며 NAS 설치·중지·업데이트, 실제 브라우저 시각 테스트 및 Docker 실행 검증은 수행하지 않았다. UI 보존 테스트는 격리된 DOM 대역 기반이다.

## 남은 확인 경계

- DSM 실기기에서 패키지 중지/업데이트 시 자식 프로세스 종료와 이어받기를 확인해야 한다. 강제 종료·전원 장애에서 완전한 체크포인트 저장을 보장하지 않는다.
- DSM 런처 handoff의 정적 파일 접근 권한과 사용 전 만료 문제는 이번 변경으로 해결했다고 주장하지 않는다. 미인증 DSM URL 및 일반 NAS 계정 접근 가능 여부를 확인한 뒤 인증 연동 발급/짧은 만료 설계를 검토해야 한다.
- HTTP는 암호화되지 않는다. 공개 HTTP 도메인 허용은 기존 요구를 유지한 것이며 신뢰하지 않는 네트워크에서는 HTTPS 역방향 프록시를 권장한다.
- 이전 버전의 범위 헤더 없는 `.more` 조각은 안전한 검증이 불가능해 다시 받을 수 있다. 이미 완료된 유효 조각은 재사용한다.
- 공급자 원본 체크섬이 없으면 자체 SHA-256 계산만으로 원본과 동일하다고 보증할 수 없다.

GitHub 게시와 NAS 설치는 이 수정 작업에 포함하지 않았다.
