# GoFile 요청량 및 연결 수 운영 지침

기록일: 2026-09-10 · 적용 기준: NASDrop 0.9.14

## 배경

사용자가 GoFile 다운로드에서 반복적인 차단과 Too Many Requests 오류를 보고했다. 요청량과 동시 연결 증가를 경계하고, 속도보다 안정적인 다운로드를 우선한다. 이는 프로젝트 운영 경험에 따른 보수적인 설계 원칙이며, GoFile의 공식 제한 수치나 개별 차단 원인이 검증됐다는 뜻은 아니다.

## 유지해야 할 규칙

- 새 GoFile 작업은 분할 모드에서도 파일당 최대 **2분할**로 받는다. 단일 연결 설정은 1개 연결을 유지한다.
- 다른 서비스의 8분할 설정을 GoFile에 일괄 적용하지 않는다. 성능 개선을 이유로 GoFile 연결 수를 임의로 늘리지 않는다.
- 기존 8분할 작업은 이어받기 데이터의 범위를 보존하되, 두 연결씩만 전송한다. 기존 조각을 새 2분할 범위로 해석하거나 무단 삭제하지 않는다.
- 이 제한은 파일당 제한이다. 여러 GoFile 작업을 동시에 실행하면 전체 연결 수가 늘어난다. 차단이 반복될 때는 같은 서비스 동시 작업도 함께 고려한다.
- 메타데이터 조회, 인증 정보 갱신, 파일 전송을 모두 요청량 관리 대상으로 본다. 큐 일괄 등록 때문에 조회를 한꺼번에 시작하거나 불필요한 재조회를 추가하지 않는다.
- HTTP 429 발생 시 메타데이터와 실제 전송이 동일한 서비스 대기 정책을 사용한다. Retry-After를 기존 안전 범위 내에서 반영하고, 같은 공급자의 작업을 지연시킨다.
- 모든 분할 연결에서 즉시 반복 재시도하지 않는다. 대기 중인 작업의 강제 재개나 무분별한 인증 갱신으로 추가 요청을 발생시키지 않는다.
- 연결 수를 줄여도 기존 차단이 즉시 해제되거나 차단이 완전히 예방된다고 안내하지 않는다.

## 변경 시 확인

- 새 2분할 작업, 단일 연결 작업, 기존 8분할 작업의 재개·결합을 각각 검사한다.
- GoFile 429가 같은 공급자의 대기 작업에도 적용되는지 검사한다.
- 다른 공급자의 분할 설정이 바뀌지 않는지 검사한다.
- `tests/test_transfer_reliability.py`와 전체 회귀 테스트를 실행한다. 실제 공급자 제한 검증을 위해 대량 요청을 보내지는 않는다.

이 문서는 운영·개발 지침이다. 아직 구현되지 않은 모든 요청 제어 기능이 이미 구현됐음을 의미하지 않는다.
